01Problem

Data discovery depended on asking the data team. The goal was a centralized, AI-powered data catalog that answers questions such as “Where can I find customer churn information?” in natural language, and tells people what each column means and how fresh the data is.

  • Create a centralized catalog for thousands of tables
  • Generate clear business descriptions for tables and columns automatically
  • Enable natural-language search over data assets
  • Reduce dependency on the data team for discovery and interpretation

02Data

Warehouse metadata: table names, column names and data types for 4,000+ tables and 20,000+ columns.

03Approach

Two pieces, built end to end:

  1. Warehouse metadataTable and column names and data types from BigQuery.
  2. AI semantic layerLLMs write business definitions for every table and column, plus how each table relates to the rest of the database and its refresh frequency.
  3. Knowledge sourceThe semantic layer becomes the agent's retrieval (RAG) source.
  4. Support agent + UIA production Next.js / TypeScript chatbot employees query in natural language.

How it evolved

  1. v1 · OpenAI APIFirst version: LLM-generated table and column descriptions used as a RAG knowledge base (published earlier as the “Data Catalog AI Agent”).
  2. Migration to GCPWhen the company adopted Google Cloud, I migrated the complete pipeline to BigQuery metadata and Vertex AI.
  3. Production agentEvolved into a security-first, cost-governed support agent for employee data discovery.

04Security & cost governance

Security-first

  1. 01
    Server-side session authNo identity or IDs trusted from the client.
  2. 02
    Input validation & prompt-injection filteringAbusive or injected prompts are blocked.
  3. 03
    Server-validated tools & guardrailsThe model can only call tools the server checks.

Cost-governed

  1. 01
    Prompt cachingReuses the large, stable context across calls.
  2. 02
    Tiered model routingSimple requests go to cheaper models.
  3. 03
    Token budgets & spend capsAn automatic kill switch keeps LLM costs predictable.

05Impact

  • Faster data discovery across thousands of tables
  • Employees find the right tables, definitions and refresh schedules on their own
  • Better data access for non-technical users
  • Fewer interruptions to the data team, and more adoption of and trust in company data
